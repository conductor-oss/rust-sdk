# Worked Examples (proposed API)

**Now implemented** — the types below (`AgentDef`, `#[tool]`, `AgentRuntime`, `Credentials`, …)
exist in `src/agents/` as proposed in [`rust-sdk-design.md`](rust-sdk-design.md), though the
snippets here were written before implementation and aren't guaranteed to compile verbatim
against the final API (e.g. builder methods that return `Result` where these examples assume
infallible chaining) — see `examples/sdk_playback_*.rs` for real, compiling, playback-verified
examples covering the same scenarios.

All three assume `--features agents` and a running Conductor server (`Configuration::from_env()`),
same as every other example in this crate.

## 1. Single agent, a tool, a guardrail — the "hello world"

Demonstrates: `#[tool]` schema derivation from a struct (not a flat function signature),
`AgentDef` builder, a guardrail, and `AgentRuntime::run` blocking to a result. This is the
minimum agent — no sub-agents, no credentials, no streaming.

```rust
use conductor::agents::{AgentDef, AgentRuntime, Guardrail, OnFail, Position, RegexGuardrail};
use conductor::agents::tool;
use conductor::{Configuration, error::Result};
use schemars::JsonSchema;
use serde::Deserialize;
use serde_json::{json, Value};

#[derive(JsonSchema, Deserialize)]
struct GetWeatherArgs {
    city: String,
}

#[tool(description = "Get current weather for a city")]
async fn get_weather(args: GetWeatherArgs) -> Result<Value> {
    // stand-in for a real weather API call
    Ok(json!({ "city": args.city, "condition": "sunny", "temp_f": 72 }))
}

#[tokio::main]
async fn main() -> Result<()> {
    let config = Configuration::from_env();
    let mut runtime = AgentRuntime::new(config)?;

    let agent = AgentDef::new("weather_assistant")?
        .with_model("openai/gpt-4o")
        .with_instructions("You are a helpful weather assistant. Use the get_weather tool.")
        .with_tool(get_weather_tool())
        // block obviously-wrong output before it reaches the caller
        .with_guardrail(Guardrail::from(
            RegexGuardrail::new(&["(?i)i don't know"])
                .mode_block()
                .position(Position::Output)
                .on_fail(OnFail::Retry)
                .max_retries(2),
        ))
        .with_max_turns(10);

    let result = runtime
        .run(&agent, json!({ "prompt": "What's the weather in Austin?" }))
        .await?;

    println!("{}", result.output);
    runtime.shutdown().await
}
```

What's happening, tied back to the design docs: `get_weather_tool()` is generated by the `#[tool]`
macro (§ Tools in `rust-sdk-design.md`) — the parameter schema comes from `GetWeatherArgs`'s
`JsonSchema` derive, not runtime introspection. `runtime.run(...)` compiles `agent` to
`agentConfig` server-side (same wire format as python-sdk for this shape — no sub-agents means no
`strategy`/`agents` keys get emitted at all, matching the "omit, don't null" contract), registers
`get_weather_tool()` as a local worker on the runtime's internal `TaskHandler`, starts the durable
workflow, and blocks until terminal.

## 2. Multi-agent handoff with a credentialed tool

Demonstrates: `Strategy::Handoff` (the default — the model decides when to delegate), a
credentialed tool (ties to `secrets-and-credentials.md`), and `allowed_transitions` as a safety
net so a misbehaving model can't route to an agent it shouldn't reach.

```rust
use conductor::agents::{AgentDef, AgentRuntime, Credentials};
use conductor::agents::tool;
use conductor::{Configuration, error::Result};
use schemars::JsonSchema;
use serde::Deserialize;
use serde_json::{json, Value};
use std::collections::HashMap;

#[derive(JsonSchema, Deserialize)]
struct SearchArgs { query: String }

// declares the credential it needs; resolved server-side, delivered on Task.runtime_metadata —
// never read from the process environment, never cached. See secrets-and-credentials.md.
#[tool(description = "Search internal GitHub issues", credentials = ["GITHUB_TOKEN"])]
async fn search_github(args: SearchArgs, creds: &Credentials) -> Result<Value> {
    let token = creds.get("GITHUB_TOKEN")?;
    let client = octocrab::Octocrab::builder().personal_token(token).build()?;
    let page = client.search().issues_and_pull_requests(&args.query).send().await?;
    Ok(json!({ "results": page.items.len() }))
}

#[tokio::main]
async fn main() -> Result<()> {
    let config = Configuration::from_env();
    let mut runtime = AgentRuntime::new(config)?;

    let triage = AgentDef::new("triage")?
        .with_model("anthropic/claude-opus-4")
        .with_instructions("Classify the user's request, then hand off to the right specialist.");

    let github_specialist = AgentDef::new("github_specialist")?
        .with_model("anthropic/claude-opus-4")
        .with_instructions("You investigate GitHub issues using the search_github tool.")
        .with_tool(search_github_tool());

    let mut allowed = HashMap::new();
    allowed.insert("triage".to_string(), vec!["github_specialist".to_string()]);

    let coordinator = AgentDef::new("support_bot")?
        .with_model("anthropic/claude-opus-4")
        .with_sub_agent(triage)
        .with_sub_agent(github_specialist)
        // Strategy::Handoff is the default once there are sub-agents — set explicitly for clarity
        .with_strategy(conductor::agents::Strategy::Handoff)
        .with_allowed_transitions(allowed)
        .with_max_turns(15);

    let handle = runtime
        .start(&coordinator, json!({ "prompt": "Find open issues mentioning 'rate limit'" }))
        .await?;

    let result = handle.join().await?;
    println!("{:?}", result.status);
    runtime.shutdown().await
}
```

Note what's *not* here: nothing reads `std::env::var("GITHUB_TOKEN")` anywhere, and nothing
mutates process environment. `search_github`'s only path to the token is the `creds` parameter,
resolved fresh per invocation from that specific `Task`'s `runtime_metadata` — if `GITHUB_TOKEN`
isn't registered as a secret on the server, this fails closed with
`ConductorError::CredentialNotFound(["GITHUB_TOKEN"])` before `search_github` ever runs, not a
confusing downstream `401` from `octocrab`.

## 3. Wrapping an existing OpenAI-style agent (`FrameworkAgent`)

Demonstrates: the `FrameworkAgent` trait from `framework-support.md` — an agent authored against
a generic OpenAI-style tool/agent shape (e.g. hand-rolled, or from an `async-openai`-based helper)
converts into an `AgentDef` via a blanket `From` impl, gaining Conductor's durability/guardrails
without its author needing to touch `AgentDef` directly.

```rust
use conductor::agents::{AgentDef, AgentRuntime, FrameworkAgent, ToolDef};
use conductor::{Configuration, error::Result};
use serde_json::json;

// Some existing struct, authored independently of Conductor, that already looks like an agent.
struct MyOpenAiAgent {
    name: String,
    system_prompt: String,
    model: String,
    tools: Vec<ToolDef>,
}

impl FrameworkAgent for MyOpenAiAgent {
    fn name(&self) -> &str { &self.name }
    fn instructions(&self) -> &str { &self.system_prompt }
    fn model(&self) -> &str { &self.model }
    fn tools(&self) -> Vec<ToolDef> { self.tools.clone() }
}

#[tokio::main]
async fn main() -> Result<()> {
    let config = Configuration::from_env();
    let mut runtime = AgentRuntime::new(config)?;

    let my_agent = MyOpenAiAgent {
        name: "release_notes_writer".into(),
        system_prompt: "Summarize merged PRs into release notes.".into(),
        model: "openai/gpt-4o".into(),
        tools: vec![], // e.g. a `fetch_merged_prs` tool, omitted for brevity
    };

    // Full extraction, always — no silent passthrough fallback (see framework-support.md).
    // If MyOpenAiAgent didn't implement FrameworkAgent, this wouldn't compile; there's no
    // runtime "detect the framework and hope" step the way python-sdk has.
    let agent: AgentDef = my_agent.into();

    let result = runtime.run(&agent, json!({ "prompt": "Summarize this week's merges" })).await?;
    println!("{}", result.output);
    runtime.shutdown().await
}
```

Because this goes through full extraction (the only mode `FrameworkAgent` supports — see
`framework-support.md`), `agent` gets a real `agentConfig` and runs through Conductor's own
`LlmChatComplete`/`DoWhile` compilation just like a hand-written `AgentDef` — guardrails and
termination conditions attached to it would actually take effect, unlike a passthrough adapter
(e.g. a hypothetical Claude Agent SDK CLI wrapper), where they wouldn't.
